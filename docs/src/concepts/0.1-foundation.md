# 0.1 Foundation

Step 0.1 turns a folder of Go files into a project you can check with one command: a git repo, a
`.gitignore`, a `go.mod`, a Makefile with `test` and `lint`, and a placeholder test in place of
tests that didn't compile.

## Modules and packages

`go.mod` names the **module**, the unit Go versions and downloads:

```
module nicoaravena/cow-book-app

go 1.27.2

tool honnef.co/go/tools/cmd/staticcheck
```

- The module path is the prefix of every import path inside it. `cowbook/` is imported as
  `nicoaravena/cow-book-app/cowbook`.
- A **package** is one directory. Every file in it starts with the same `package` line and sees
  every other file's names, exported or not. Splitting a package into files is only for readers.
- The `go` line is the language version the code is written for. It also turns on features that
  depend on it, such as per-iteration loop variables (1.22).
- `go.sum` records a hash of every dependency, so a build fails rather than use a changed download.
  Both files are committed.

## `go tool` dependencies

The `tool` line (Go 1.24) records a program the project runs, here `staticcheck`, with its version
pinned in `go.mod` like any library. `go tool staticcheck ./...` builds and runs that exact version.
No global install, and everyone runs the same one.

## The Makefile

```make
test:
	go test ./...

lint:
	go vet ./...
	@unformatted="$$(gofmt -l .)"; \
	if [ -n "$$unformatted" ]; then \
		echo "gofmt needed on:"; echo "$$unformatted"; exit 1; \
	fi
	go tool staticcheck ./...
```

- `./...` means this directory and every package below it.
- `go vet` finds code that compiles but is very likely wrong: a `Printf` verb that doesn't match its
  argument, a copied mutex, unreachable code.
- `gofmt -l` lists files whose formatting differs from the one standard layout. It prints nothing
  when all is well, which is why the recipe fails only on non-empty output. There is no style debate
  in Go: `gofmt` decides.
- `staticcheck` adds checks `vet` doesn't have: unused code, deprecated calls, simplifications.
- `$$` in a Makefile is a literal `$` for the shell.

## Tests

A test is a function `TestXxx(t *testing.T)` in a file ending in `_test.go`, in the same package as
the code. `go test` builds those files only for testing, so they never ship.

```go
// TestZeroValueSpace checks that a Space declared without values starts
// with an unset ID. Step 1.1 replaces this with tests for NewSpace.
func TestZeroValueSpace(t *testing.T) {
	var s Space
	if s.ID != 0 {
		t.Errorf("zero value Space has ID = %d, want 0", s.ID)
	}
}
```

- There is no assertion library. A test compares and calls `t.Errorf` (report, keep going) or
  `t.Fatalf` (report, stop this test).
- Messages read `got = X, want Y`, so a failure explains itself without opening the test.

## Zero values

Every Go type has a **zero value**: `0`, `""`, `false`, `nil`, and for a struct, every field at its
own zero value. `var s Space` is a usable `Space`, not an uninitialised one. Later steps lean on
this: a zero `time.Time` means "not set" (1.6), a zero `sync.Mutex` is unlocked (1.8), and a zero
`role` means "no role" (1.4).
