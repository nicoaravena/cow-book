# 1.6 Who can book

Step 1.6 makes booking depend on who asks. A member books only for themselves, front desk staff for
any member at their locations, an admin for any member. A booking made by staff starts **pending**:
the member must approve it before its approval deadline, and until then it holds the slot.
`Booking.Approve` and `BookingService.Approve` are new; declining is the existing `Cancel`.

## One permission rule for book and cancel

```go
// actsFor reports whether a may book or cancel for the member with memberID at
// locationID.
func (a Actor) actsFor(memberID, locationID int64) bool
```

1.4's `canCancel(b Booking, locationID)` becomes `actsFor(memberID, locationID)`. It no longer needs
a whole booking, so `NewBooking` can call it before a booking exists. It's the first `case` in
`NewBooking`:

```go
case !actor.actsFor(p.MemberID, space.locationID):
	return Booking{}, ErrBookNotAllowed
```

`BookingService.Book` now runs `NewBooking` before loading the member, so a refused actor can't
tell a deleted member from an existing one.

## State from zero-value timestamps

There is no `status` field. A booking's state comes from which timestamps are set:

```go
approvalDeadline time.Time // zero when no approval is needed
approvedAt       time.Time // zero until approved
cancelledAt      time.Time // zero until cancelled
```

| `approvalDeadline` | `approvedAt` | `cancelledAt` | State |
| --- | --- | --- | --- |
| zero | zero | zero | Confirmed (member booked it) |
| set | zero | zero | Pending, or lapsed once `now` is past the deadline |
| set | set | zero | Approved |
| any | any | set | Cancelled |

- A status field and timestamps can disagree (`status = approved`, no `approvedAt`). Timestamps
  alone can't, and they also say **when**, which the history needs.
- "Lapsed" isn't stored at all: it depends on the time you ask. That's why lapsed bookings are
  cancelled lazily, when someone needs their slot (2.5).

## The deadline

```go
if actor.role != roleMember {
	b.bookedBy = actor.id
	b.approvalDeadline = now.Add(approvalWindow)
	if p.Start.Before(b.approvalDeadline) {
		b.approvalDeadline = p.Start
	}
}
```

24 hours after creation, or the booking's start if sooner: a member can't approve a booking that has
already begun. `approvalWindow` is an unexported constant.

## Unexported helper methods

```go
// awaitingApproval reports whether b was made by staff and the member hasn't
// approved it yet. It doesn't look at cancellation or the deadline.
func (b Booking) awaitingApproval() bool {
	return !b.approvalDeadline.IsZero() && b.approvedAt.IsZero()
}
```

A lowercase method names a condition so `Approve`'s `switch` reads as rules, and stays out of the
public API. Its comment says what it does **not** check, so no one uses it as "is pending" alone.

## `Approve`

```go
func (b *Booking) Approve(actor Actor, now time.Time) error {
	switch {
	case actor.role != roleMember || actor.id != b.memberID:
		return ErrApproveNotAllowed
	case !b.cancelledAt.IsZero():
		return ErrAlreadyCancelled
	case !b.awaitingApproval():
		return ErrNotPending
	case !now.Before(b.approvalDeadline):
		return ErrApprovalExpired
	}
	...
}
```

Only the member themselves, not staff: approval is the member's consent. Permission first, as in
`Cancel`. Approving races cancelling and other approvals, so `SaveApproval` lets the store pick the
winner, with `ErrAlreadyCancelled` or `ErrNotPending` for the loser.
