# 1.4 Members and actors

Step 1.4 adds `Member` (`NewMember`, soft `Delete`), `Actor` (who is asking: a member, front desk
staff with locations, or an admin) and `Booking.Cancel`, the first rule that depends on who asks.

## Pointer vs value receivers

```go
func (m *Member) Delete(now time.Time) error {
	if !m.deletedAt.IsZero() {
		return ErrMemberDeleted
	}
	m.deletedAt = now
	m.updatedAt = now
	return nil
}
```

- A **value receiver** `(m Member)` gets a copy. Changing it changes nothing the caller sees.
- A **pointer receiver** `(m *Member)` gets the address of the caller's value, so changes stick.

Rule of thumb used here: a method that changes the value takes a pointer; one that only reads takes
a value. `Delete` and `Booking.Cancel` take pointers.

Calling a pointer method on an addressable variable works without `&`: `m.Delete(now)` is
`(&m).Delete(now)`. It fails on values that have no address, such as a map element
(`members[3].Delete(now)` doesn't compile), which 1.7 runs into with slices.

## Validate everything before changing anything

`Delete`, `Cancel` and later `Approve` all check first, then assign. If any check fails they return
before touching a field, so "on error the booking is unchanged" holds without any undo logic.

## Small enums with `iota`

```go
type role int

const (
	roleMember role = iota + 1
	roleFrontDesk
	roleAdmin
)
```

- `iota` counts up within a `const` block: 0, 1, 2. A line with no expression repeats the previous
  one, so these are 1, 2, 3.
- **`+ 1` on purpose.** The zero value of `role` is 0, which is no role at all. An `Actor{}` built
  by mistake falls into the `switch`'s final `return false` and can do nothing. Starting at 0 would
  make every forgotten field a member.
- `role` is unexported, so outside `cowbook` the only way to make an `Actor` is `MemberActor`,
  `FrontDeskActor` or `AdminActor`.

## Defensive copies

```go
func FrontDeskActor(id int64, locations []int64) Actor {
	return Actor{id: id, role: roleFrontDesk, locations: slices.Clone(locations)}
}
```

A slice shares its backing array. Storing the caller's slice would let the caller change what the
Actor may do later, by writing to their own slice. `slices.Clone` cuts that link.

## Who can cancel

```go
func (a Actor) canCancel(b Booking, locationID int64) bool {
	switch a.role {
	case roleMember:
		return a.id == b.memberID
	case roleFrontDesk:
		return slices.Contains(a.locations, locationID)
	case roleAdmin:
		return true
	}
	return false
}
```

IDs are compared only for members: members and staff are separate tables, so staff 3 is not member
3. 1.6 generalises this to `actsFor(memberID, locationID)` so booking can share it.

`Cancel` takes the booking's `Space`, because the location decides what front desk staff may do and
a `Booking` holds only a space ID. A space that isn't the booking's own is refused rather than
trusted. Permission is checked first, so someone who isn't allowed learns nothing about the booking
(not even that it's already cancelled).

## Validating emails

```go
func validEmail(email string) bool {
	addr, err := mail.ParseAddress(email)
	return err == nil && addr.Address == email
}
```

`net/mail.ParseAddress` parses RFC 5322 addresses, which include `"Ana <ana@x.com>"`. Requiring the
parsed address to equal the input keeps only bare addresses. `NewMember` lowercases the email first,
because it must be unique per operator.

## Soft delete

Deleting a member sets `deletedAt` and keeps the row, so old bookings still point at a real member.
A second delete returns `ErrMemberDeleted`. 1.7 adds what deletion does to their bookings.
