# 1.9 REPL

Step 1.9 adds `cmd/cowbook`, the app's one binary, with its first subcommand: `repl`, a small
command prompt over the in-memory store and `BookingService`. Until now every rule lived only in
tests. From this step on, each step grows this binary, so you can watch the step work; at the last
step `cowbook serve` runs the full app.

```sh
go run ./cmd/cowbook repl          # type help
```

A short tour of 1.1-1.8 to type or paste:

```text
space add Room-A meeting_room 6 2h
space add Desk-1 hot_desk 1 4h mon-fri/09:00-13:00,sat/10:00-14:00 Europe/Madrid
member add Ana ana@example.com
member add Bo bo@example.com
as member 1
book 1 2026-11-16 09:00-10:00
book 1 2026-11-16 10:00-11:00 7
book 1 2026-11-16 11:00-12:00 for 2
as frontdesk 7 1
book 1 2026-11-16 11:00-12:00 for 2
as member 1
book 1 2026-11-16 11:30-12:30
clock add 2h
book 1 2026-11-16 09:00-09:30
```

The command list is in the [REPL reference](../reference/repl.md).

## A delivery adapter

The REPL sits where HTTP handlers will sit in M3: it turns input into a service call and the result
into output, and decides nothing. `book` parses words into a `BookingParams`, calls
`BookingService.Book`, and prints the booking or the error. It never checks capacity or opening
hours itself; the errors you see are the domain's sentinels, printed with `%v`:

```text
[member 1]> book 1 2026-11-16 10:00-11:00 7
error: booking exceeds the space's capacity: 7 attendees, capacity 6
```

Two places come close to rules and hand them back to the domain instead:

- `parseClock` checks `HH:MM` by calling `cowbook.NewClockTime`, so the REPL and the domain agree
  on what `24:00` or `09:60` mean.
- `as member 9` is accepted even if member 9 doesn't exist. Whether they may book is the
  service's question, asked on the next `book`.

`cmd/cowbook/main.go` is the composition root: the `repl` subcommand builds the clock, store and
service and passes them in. `internal/repl` imports nothing global, which is what makes it testable.

## Subcommands with `os.Args`

```go
switch os.Args[1] {
case "repl":
	err = runREPL()
default:
	fmt.Fprintf(os.Stderr, "cowbook: unknown command %q\n%s\n", os.Args[1], usage)
	os.Exit(2)
}
```

`os.Args[0]` is the program's name and the rest are its arguments. With one subcommand, a `switch`
is enough; 3.2 moves to the `flag` package when subcommands start taking options. Usage goes to
stderr, so stdout stays the command's output, and a usage error exits with `2`, a general error with
`1`.

## `io.Reader` and `io.Writer`

```go
func (s *Session) Run(ctx context.Context, in io.Reader, out io.Writer, script bool) error
```

`Run` doesn't know about `os.Stdin` or the terminal. `main` passes `os.Stdin` and `os.Stdout`; the
tests pass a `strings.Reader` and a `strings.Builder`:

```go
var out strings.Builder
in := strings.NewReader("clock\n")
err := s.Run(context.Background(), in, &out, false)
```

`io.Reader` has one method, `Read(p []byte) (n int, err error)`, and `io.Writer` one,
`Write(p []byte) (n int, err error)`. Files, network connections, buffers and strings all
implement them, so code written against them works with any of these. It is the same idea as the
injected clock in 1.5, applied to input and output.

`fmt.Fprintf(out, ...)` writes to any `io.Writer`; `fmt.Printf` is just `Fprintf(os.Stdout, ...)`.

## Reading lines with `bufio.Scanner`

```go
sc := bufio.NewScanner(in)
for sc.Scan() {
	line := sc.Text()
	...
}
return sc.Err()
```

`Scan` reads up to the next newline and returns `false` at the end of input or on an error. `Text`
returns the line without its newline. After the loop, `Err` tells the two apart: it is `nil` at a
clean end of input. Lines longer than 64 KiB are an error unless you call `sc.Buffer`, which is
plenty for a prompt.

`Run` uses `for { ... if !sc.Scan() { break } ... }` instead, because in interactive mode the
prompt must print *before* waiting for the line.

## Splitting words

- `strings.Fields(line)` splits on any run of spaces and tabs and drops empty strings, so
  `"  book  1 "` gives `["book", "1"]`. This is why names are one word: there is no quoting.
- `strings.Cut(s, "/")` splits at the first `/` and reports whether it found one:
  `before, after, found`. It replaces most `strings.Index` plus slicing.
- `strings.SplitSeq(s, ",")` (Go 1.24) returns an iterator over the parts, used with `range`,
  without building a slice. `strings.Split` returns the slice.

## A map of command functions

```go
s.commands = map[string]command{
	"book":  {"book <spaceID> ...", "book a space, in the space's timezone", s.book},
	"clock": {"clock [set ... | add <duration>]", "show or move the session's time (UTC)", s.clockCmd},
	...
}
```

`s.book` is a **method value**: a function with the receiver `s` already bound, so its type is
`func(context.Context, []string) (string, error)`, the same as the `run` field. The loop looks up
the first word and calls `cmd.run(ctx, words[1:])` without a `switch` over command names. Adding a
command is one map entry and one method.

Maps iterate in random order, so `help` sorts the names first:
`slices.Sorted(maps.Keys(s.commands))`. `maps.Keys` returns an iterator and `slices.Sorted`
collects and sorts it.

## Errors for control flow

Commands return errors; the loop decides what to print:

```go
switch {
case errors.Is(err, errQuit):
	return nil
case errors.Is(err, errUsage):
	fmt.Fprintf(out, "error: usage: %s\n", cmd.usage)
case err != nil:
	fmt.Fprintf(out, "error: %v\n", err)
}
```

`errQuit` and `errUsage` are unexported sentinels, like the domain's but private to the package. A
command says "show my usage" by returning `errUsage`, without knowing its own usage text. A domain
error is never fatal: the REPL prints it and reads the next line.

## Parsing times

```go
day, err := time.Parse("2006-01-02", date)
```

Go layouts are written as one reference moment, `Mon Jan 2 15:04:05 MST 2006`. In the American
order `01/02 03:04:05PM '06 -0700` it counts 1 to 7: month, day, hour, minute, second, year, zone. `2006-01-02` means year-month-day and `15:04` a
24-hour time. The REPL prints with `"Mon 2006-01-02 15:04 MST"`. `time.Parse` without a zone gives
UTC.

A booking's date and times are wall-clock readings at the space, so `book` asks the store for the
space's `*time.Location` first, then builds each instant with:

```go
start = time.Date(y, m, d, from.hour, from.minute, 0, 0, loc)
```

`time.Date` normalizes out-of-range values: hour 24 becomes 00:00 the next day, which is exactly
what an end of `24:00` should mean. It also means `parseClock` must refuse `25:00` itself, or it
would quietly become 01:00 tomorrow.

`time.ParseDuration` reads `90m`, `2h30m`, `25h`, used for `clock add` and a space's max length.

## Terminal or script?

```go
info, err := os.Stdin.Stat()
script := err == nil && info.Mode()&os.ModeCharDevice == 0
```

A terminal is a character device; a file redirected with `<`, a heredoc or a pipe is not. `Mode()` returns
bits, and `&` keeps only the `ModeCharDevice` bit, so the expression is zero when stdin is not a
terminal. In script mode the REPL echoes each line after its prompt, because nobody typed it on
screen.

## A settable clock

`Clock` holds a `time.Time`, and `main` passes its method value `clock.Now` to
`NewBookingService`. The service then reads whatever time the session has set, so `clock add 2h`
makes 09:00 "the past" and will make approval deadlines pass in 1.10. It is the injected clock from
1.5, driven by hand. One goroutine runs the session, so the clock has no mutex.

## What the tests cover

`internal/repl/repl_test.go` runs short scripts through a real store and service and checks what
was printed: one full transcript, each booking rule as an error line, staff bookings pending with
their deadline, the clock, hours and timezones (including `24:00` and a Madrid space), `help`,
`quit`, unknown commands and usage errors, and interactive mode printing prompts without echo.
`TestBookingAccessors` covers the new `Booking.ApprovalDeadline`.
