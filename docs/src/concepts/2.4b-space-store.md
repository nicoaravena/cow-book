# 2.4b Space store

Step 2.4b is the first store on top of 2.4's plumbing:

- **`postgres.SpaceStore`** creates, gets and lists one tenant's spaces, each call in one
  `WithTenant` transaction. It implements `cowbook.SpaceStore`, the interface `BookingService`
  reads spaces through.
- **`cowbook.RestoreSpace`** rebuilds a `Space` from stored values, and `Space` gets the
  accessors a store needs to write one: `LocationID`, `Hours`, `Available`, `CreatedAt`,
  `UpdatedAt`. `WeeklyHours.Windows` and `ClockTime.Minutes` turn opening hours into rows.

The REPL still runs on the in-memory store until 2.7, so the runnable result is the tests:

```sh
just db-up migrate-platform                # as in 2.1
just generate                              # no diff expected
just test-integration
go test -race -tags integration -run SpaceStore -v ./internal/postgres
```

The last command lists each case:

```text
--- PASS: TestSpaceStoreCreateAndGet
--- PASS: TestSpaceStoreUnavailableRoundTrip
--- PASS: TestSpaceStoreGetMissing
--- PASS: TestSpaceStoreOtherTenant
--- PASS: TestSpaceStoreUnknownLocation
--- PASS: TestSpaceStoreList
--- PASS: TestSpaceStoreBadTimezone
--- PASS: TestSpaceStoreNoWindows
```

The reference is in [Stores](../reference/stores.md#internalpostgres) and

## Mapping rows to domain types

sqlc generates one Go type per table, shaped like the table: `tenantdb.Space` has `Capacity int32`
because the column is `integer`, and `MaxBookingLength pgtype.Interval` because it is `interval`.
`cowbook.Space` is shaped by the rules instead: `int`, `time.Duration`, a `SpaceKind`. The store
sits between the two and converts in both directions, in one place, `spaceFromRow` and
`CreateSpace`.

Most conversions are Go conversions, `int32(sp.Capacity())` one way and `int(row.Capacity)` the
other. A conversion between integer types never fails; a value too big for `int32` would wrap
around silently. Capacity is small in practice and the table refuses anything below 1.

`pgtype` holds Postgres types Go has no exact match for. Each has a `Valid` field, `false` for
`NULL`, like 2.2's [`NULL` vs zero values](2.2-tenant-schemas.md#the-tenant-tables). An
`interval` is three numbers, not one:

```go
type Interval struct {
	Microseconds int64
	Days         int32
	Months       int32
	Valid        bool
}
```

Postgres keeps them apart because a day is not always 24 hours (a clock change) and a month has
no fixed length. `durationToInterval` writes only microseconds. Reading back, `intervalToDuration`
counts a day as 24 hours, the way Postgres compares intervals, so a `'1 day'` typed in `psql`
reads as `24h`. It refuses months: there is no right answer, and the table's check keeps them out.

## Opening hours as rows

A `WeeklyHours` is one value in Go and several rows in `opening_windows`. Writing, the store asks
for `sp.Hours().Windows()`, a new slice, Sunday first and each day by opening time, and inserts
one row per window with `ClockTime.Minutes()`, the minutes since midnight that `opens_min` and
`closes_min` hold. All of it happens inside the one `WithTenant`, so a failed window insert rolls
the space back too.

Reading, it turns each row back with `NewClockTime(m/60, m%60)` and builds the week with
`NewWeeklyHours`, which checks the windows again.

## Rebuilding through the constructor

`Space`'s fields are unexported, so only package `cowbook` can fill one in. `NewSpace` can't
rebuild a stored space on its own: it always starts available, with no ID and both timestamps set
to `now`. `RestoreSpace` does the rest:

```go
func RestoreSpace(r SpaceRecord) (Space, error) {
	s, err := NewSpace(r.SpaceParams, r.CreatedAt)
	if err != nil {
		return Space{}, err
	}
	s.ID = r.ID
	s.available = r.Available
	s.updatedAt = r.UpdatedAt
	return s, nil
}
```

Going through `NewSpace` means every row is checked by the same rules as a new space. A row
someone changed by hand into something the domain refuses comes back as an error naming the rule,
not as a `Space` that breaks a booking later. `TestSpaceStoreNoWindows` deletes a space's windows
behind the store's back and gets `ErrNoOpeningHours`. The cost: if a rule tightens one day, rows
that met the old rule stop loading until a migration fixes them.

## Embedded structs

```go
type SpaceRecord struct {
	ID int64
	SpaceParams
	Available bool
	CreatedAt time.Time
	UpdatedAt time.Time
}
```

`SpaceParams` with no field name is **embedded**. The record has a field called `SpaceParams`,
and its fields are **promoted**: `r.Name` means `r.SpaceParams.Name`. So the record is the
params plus what a store adds, without repeating six fields, and `RestoreSpace` can hand
`r.SpaceParams` to `NewSpace` whole. A composite literal still names it:
`SpaceRecord{ID: 7, SpaceParams: p}`. Embedding isn't inheritance: a `SpaceRecord` isn't a
`SpaceParams` and can't be passed as one.

## Timestamps lose their nanoseconds

`CreateSpace` stores the timestamps the domain set, from the injected clock, rather than the
column default `now()`, so the clock stays the one source of time. Go keeps nanoseconds, Postgres
microseconds. `TestSpaceStoreCreateAndGet` creates a space at `10:00:00.123456789` and reads back
`10:00:00.123456`: pgx sends a `timestamptz` in binary as whole microseconds, and the integer
division drops the rest. Postgres given the same time as text rounds instead, to `.123457`.

Two things follow. Compare times with `Equal`, not `==`: pgx also hands times back in
`time.Local`, so the same instant has a different location. And a space just created has more
precision than the same space read back. Nothing compares them yet; 2.5 has to keep it in mind
for booking times.

## Foreign key errors

A space at a location the tenant doesn't have breaks `spaces_location_id_fkey`. Rather than read
the location first, which another request could delete in between, the store inserts and reads
the error, as 2.2 did for the slug
([`errors.As`](2.2-tenant-schemas.md#checking-which-constraint-refused-a-row)):

```go
var pgErr *pgconn.PgError
if errors.As(err, &pgErr) && pgErr.Code == "23503" && pgErr.ConstraintName == "spaces_location_id_fkey" {
	return cowbook.Space{}, cowbook.ErrInvalidLocation
}
```

`23503` is `foreign_key_violation`. `WithTenant` wraps the error, and `errors.As` looks through
the wrapping. The caller gets the domain's own `ErrInvalidLocation`, the error `NewSpace` gives
for a location ID of 0, and never sees a Postgres code.

## Two queries, not one per space

`ListSpaces` could call `GetSpace` for each space, one query for the list plus one per space. That
is the **N+1** pattern: cheap with three spaces, slow with three hundred, and each query here is
two round trips because of `describe_exec`. Instead it reads every window in a second query,
ordered by space, and groups them in a map:

```go
bySpace := make(map[int64][]tenantdb.OpeningWindow)
for _, w := range windows {
	bySpace[w.SpaceID] = append(bySpace[w.SpaceID], w)
}
```

`append` on a missing key works because a map returns the zero value, a nil slice, and appending
to nil allocates. A space with no windows gets `bySpace[row.ID] == nil` and fails in
`RestoreSpace`, as above.

`GetSpace` uses `sqlc.embed(spaces)` in its query, so its row is a `tenantdb.Space` plus the
location's `timezone`. Both methods then share `spaceFromRow`.

## A store bound to one tenant

`cowbook.SpaceStore` has `GetSpace(ctx, id)` with no tenant: the domain knows nothing of tenants.
So the tenant goes in the store, `NewSpaceStore(pool, tenantID)`. The struct is two fields and
holds no connection, so M3 can build one per request once the tenant middleware has resolved the
slug. `TestSpaceStoreOtherTenant` checks that a space's ID read through another tenant's store is
`ErrSpaceNotFound`: each store only ever sees its own schema.

`var _ cowbook.SpaceStore = (*SpaceStore)(nil)` makes the compiler check the interface, as in
[1.8](1.8-in-memory-store.md#compile-time-interface-checks).

## Known gaps

- Spaces can only be created and read. Changing one (hours, availability) arrives with space
  management in 3.7, which will set `updated_at`.
- `GetSpace` returns a `*time.Location`, not a `Location` type; that arrives in 3.7 too.
- An invalid timezone is only found when a space is read. Checking it when a location is created
  is 3.7's job.
- `SpaceStore.CreateSpace` returns the ID, while `memstore.AddSpace` takes one. 2.7 gives the REPL
  an interface both stores meet.
