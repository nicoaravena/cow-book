# 1.5 Services and stores

Step 1.5 adds `cowbook/service.go`: three store interfaces (`BookingStore`, `SpaceStore`,
`MemberStore`) and `BookingService`, which loads what the domain rules need, applies them and saves
the result. The domain still imports nothing about databases.

## Implicit interfaces

```go
type SpaceStore interface {
	GetSpace(ctx context.Context, id int64) (Space, *time.Location, error)
}
```

An interface is a set of method signatures. A type **implements** it by having those methods; there
is no `implements` keyword. So:

- `cowbook` declares the interfaces it needs, and `internal/postgres` (M2) will implement them
  without `cowbook` importing it. Dependencies point inward, at the domain.
- A test fake implements them the same way. `fakeStore` in `service_test.go` implements all three
  with maps and records every call.
- Go style is to define an interface where it's **used**, not where it's implemented, and to keep it
  small. Three small ones instead of one big `Store` let 2.4 build the space store on its own.

1.8 adds a compile-time check that a type implements an interface.

## `context.Context`

Every store method takes a `ctx` first. A context carries a deadline, a cancellation signal and
request-scoped values down the call chain. When an HTTP client disconnects (M3), its context is
cancelled and the database query stops instead of finishing for nobody.

Conventions: `ctx` is the first parameter, it's never stored in a struct, and a function that
receives one passes it on. A test puts a value in the context and checks every store call got that
same context.

## Dependency injection, including the clock

```go
type BookingService struct {
	bookings BookingStore
	spaces   SpaceStore
	members  MemberStore
	now      func() time.Time
}

func NewBookingService(bookings BookingStore, spaces SpaceStore, members MemberStore, now func() time.Time) *BookingService
```

- The service gets its stores from the caller instead of creating them. `main` (3.1) passes real
  ones; tests pass the fake: `NewBookingService(store, store, store, ...)`.
- **Functions are values.** `now` is a field of type `func() time.Time`. Production passes
  `time.Now` (the function itself, no call). Tests pass `func() time.Time { return fixed }`, so
  "not in the past" and "deadline passed" are tested at an exact time.
- `NewBookingService` returns a pointer: the service is shared and has no value semantics.

## A service is thin

```go
func (s *BookingService) Cancel(ctx context.Context, actor Actor, bookingID int64) (Booking, error) {
	b, err := s.bookings.GetBooking(ctx, bookingID)
	if err != nil {
		return Booking{}, err
	}
	space, _, err := s.spaces.GetSpace(ctx, b.spaceID)
	if err != nil {
		return Booking{}, err
	}
	if err := b.Cancel(actor, space, s.now()); err != nil {
		return Booking{}, err
	}
	if err := s.bookings.SaveCancellation(ctx, b); err != nil {
		return Booking{}, err
	}
	return b, nil
}
```

Load, apply the domain rule, save. The rule lives in `Booking.Cancel`; the service decides only the
order of calls. `_` discards a result that isn't needed (the timezone here).

Errors come back **as they are**: no wrapping, no translation. Callers check them with `errors.Is`
against the sentinels in `cowbook`.

## Read, check, write

`Cancel` reads the booking, checks it, then writes. Two requests can both read "not cancelled" and
both pass. So the interface comment makes the store responsible: `SaveCancellation` must give the
loser `ErrAlreadyCancelled`. The same goes for `CreateBooking` and `ErrSlotTaken`. 1.8 shows why
only the store can decide.

## `Book` at this step

`Book(ctx, spaceID, p)` took no actor: the caller had to decide who may book for whom. It also
refused a deleted member before checking the booking. 1.6 adds the actor and moves that check after
`NewBooking`.
