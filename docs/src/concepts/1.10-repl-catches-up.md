# 1.10 REPL catches up

Step 1.10 lets the REPL reach everything M1 built: `cancel`, `approve`, `member delete`, and
listings of spaces, members and bookings with their state. Until now `Cancel`, `Approve` and
`MemberService.Delete` ran only in tests, and nothing showed what the store held.

```sh
go run ./cmd/cowbook repl
```

A tour to type or paste:

```text
space add Room-A meeting_room 6 2h
member add Ana ana@example.com
member add Bo bo@example.com
as admin 9
book 1 2026-11-16 11:00-12:00 for 2
book 1 2026-11-16 10:00-11:00 for 2
as member 2
approve 1
as member 1
book 1 2026-11-16 09:00-10:00
book 1 2026-11-16 16:00-17:00
cancel 3
clock add 4h
booking list
member delete 1
booking list
member list
space list
```

After `clock add 4h` it is 12:00, past the 10:00 deadline (its start) of booking 2, which Bo never approved:

```text
[member 1]> booking list
ID  SPACE  MEMBER  WHEN                            ATTENDEES  STATE
1   1      2       Mon 2026-11-16 11:00-12:00 UTC  1          confirmed
2   1      2       Mon 2026-11-16 10:00-11:00 UTC  1          expired
3   1      1       Mon 2026-11-16 09:00-10:00 UTC  1          cancelled
4   1      1       Mon 2026-11-16 16:00-17:00 UTC  1          confirmed
```

Deleting Ana then cancels booking 4, which hasn't ended. Booking 3 was cancelled already.

## Lining up columns with `text/tabwriter`

```go
func table(header []string, rows [][]string) string {
	var b strings.Builder
	w := tabwriter.NewWriter(&b, 0, 0, 2, ' ', 0)
	fmt.Fprintln(w, strings.Join(header, "\t"))
	for _, row := range rows {
		fmt.Fprintln(w, strings.Join(row, "\t"))
	}
	w.Flush()
	return strings.TrimSuffix(b.String(), "\n")
}
```

A `tabwriter.Writer` is an `io.Writer` that wraps another one. You write cells separated by `\t`;
it pads every cell of a column to the column's widest cell. It can't know that width until it has
seen the last row, so it **buffers** everything and writes only on `Flush`. Forget `Flush` and the
output is empty.

The arguments to `NewWriter(output, minwidth, tabwidth, padding, padchar, flags)`:

| Argument | Here | Means |
| --- | --- | --- |
| `minwidth` | `0` | Narrowest a column may be |
| `tabwidth` | `0` | Only used when `padchar` is `'\t'` |
| `padding` | `2` | Spaces added after the widest cell, the gap between columns |
| `padchar` | `' '` | Pad with spaces, so the output looks the same in any terminal |
| `flags` | `0` | E.g. `tabwriter.AlignRight` for numbers, `tabwriter.Debug` to draw `|` between columns |

A cell ends at a `\t`. The last cell of a line has no `\t` after it, so it isn't part of a column
and gets no trailing spaces. That keeps the test's expected output free of invisible padding.

`table` returns a string, not writes to `out`, because every command returns its answer and `Run`
prints it. The answer ends without a newline, since `Run` adds one.

## Map order and `slices.SortFunc`

The in-memory store keeps bookings in a `map[int64]cowbook.Booking`. Ranging over a map gives the
entries in an **order Go randomizes on purpose**, so code can't come to depend on it. A list that
comes straight from the map would print in a different order every run.

`ListBookings` collects the values and sorts them by ID:

```go
bookings := make([]cowbook.Booking, 0, len(s.bookings))
for _, b := range s.bookings {
	bookings = append(bookings, b)
}
slices.SortFunc(bookings, func(a, b cowbook.Booking) int { return cmp.Compare(a.ID, b.ID) })
```

- `make([]T, 0, n)` makes an empty slice with room for `n`, so `append` never has to grow it.
- `slices.SortFunc` sorts in place with a comparison function that returns a negative number,
  zero or a positive number, like `strings.Compare`.
- `cmp.Compare(a, b)` does that for any ordered type: ints, floats, strings.

`help` in 1.9 used `slices.Sorted(maps.Keys(m))` because it sorted the keys themselves, which are
ordered. A `Booking` isn't ordered, so it needs a function that says how to compare two.

Postgres has the same rule: a `SELECT` without `ORDER BY` has no defined order.

## A booking's state belongs to the domain

The list shows each booking as `confirmed`, `pending`, `expired` (what 1.6 calls lapsed) or
`cancelled`. Reading that off
the timestamps is a rule: a pending booking expires at its deadline, the same moment `Approve`
starts returning `ErrApprovalExpired`. If the REPL worked it out, the HTTP API in M3 would work it
out again, and the two could disagree. So it is a domain method:

```go
func (b Booking) State(now time.Time) BookingState {
	switch {
	case !b.cancelledAt.IsZero():
		return StateCancelled
	case b.awaitingApproval() && !now.Before(b.approvalDeadline):
		return StateExpired
	case b.awaitingApproval():
		return StatePending
	}
	return StateConfirmed
}
```

`BookingState` is a string type like `SpaceKind` in 1.1, so `string(b.State(now))` is ready to
print or send as JSON. It takes `now` because a booking can expire without anything about it
changing; the REPL passes its session clock. The rules themselves still read the timestamps, not
`State`, so the label can never decide anything.

An approved booking shows as `confirmed`: once approved it behaves exactly like one the member
made. An `expired` booking still holds its slot in the in-memory store. 2.5 cancels it lazily in
Postgres.

## More accessors

The lists need a space's name and kind and a member's name and email, all unexported. The step
adds read-only accessors (`Space.Name`, `Kind`, `Capacity`, `MaxBookingLength`, `Member.Name`,
`Email`, `Booking.Attendees`), the same pattern as `Booking.SpaceID` in 1.8. Code outside `cowbook`
can read a space but still not change it.

## List methods stay off the interfaces

`ListSpaces`, `ListMembers` and `ListBookings` are methods of `*memstore.Store` only, not part of
`BookingStore`, `SpaceStore` or `MemberStore`. No service needs them: the REPL calls the store
directly to read, as it already does with `AddSpace`. Putting them in the interfaces now would make
the Postgres store implement them in M2 for no caller. When an HTTP endpoint needs a list (M3), the
interface gains the method it needs, probably filtered and paged rather than "everything".

Commands that change something still go through the services: `cancel` calls
`BookingService.Cancel`, never `store.SaveCancellation`.

## Commands with sub-verbs

`space`, `member` and `booking` each take a verb, dispatched with a `switch` on the argument count
and the first word:

```go
switch {
case len(args) == 3 && args[0] == "add":
	return s.memberAdd(args[1], args[2])
case len(args) == 2 && args[0] == "delete":
	return s.memberDelete(ctx, args[1])
case len(args) == 1 && args[0] == "list":
	return s.memberList(ctx)
}
return "", errUsage
```

Checking the length in the same case as the word means each helper gets exactly the arguments it
needs and never indexes past the end.

## What the tests cover

- `TestBookingState` in `cowbook/booking_test.go`: own booking, pending, at and after the deadline,
  approved, declined, cancelled.
- `TestLists` in `internal/memstore`: sorted by ID, cancelled bookings and deleted members
  included. `TestDoneContextIsRefused` covers the new methods.
- `internal/repl/repl_test.go`: one full transcript ending in all three lists, empty lists, and a
  table of `cancel`, `approve` and `member delete` cases: wrong member, staff approving, after the
  deadline, twice, unknown IDs, a deleted member, usage errors and nobody acting.
